# firmware-ps2 — 20261011-050536-b83b06d

- **Record ID**: 20261011-050536-b83b06d
- **Claim**: target-spec row 13 (**stretch column**: a protocol in a role and pin direction the core protocols never use), RTL leg; `spec/verification-plan.md` §7 "Unplanned-protocol firmware (row 13)". The committed program `firmware/asm/ps2_device.asm` (image `firmware/build/ps2_device.hex`, 213 words), loaded over the serial load-phase pins onto the RTL top and run by the ISA core, behaves as a PS/2 keyboard/mouse **device** on an open-drain, pulled-up two-wire bus (CLK `uio[2]`, DATA `uio[3]`, DR 0012 `UIO_OD` = 0x0C) that a host also drives. The independent host model `verification/reference_models/ps2.py` (written from Chapweske's description, DR 0018's note of 2026-10-11) grades every edge the device makes and the bench's own host driver; the silicon-true pad model (`verification/uio_pads.py`) resolves the lines and reports contention. The protocol was chosen by the dated note in DR 0018 (Proposed), committed after DR 0017's ISA freeze at merge commit `1696045bfa1a33f93c95a5bf6c29b05f4ea0d734`; no pinned file differs from the freeze (`scripts/check_isa_freeze.py`: 2 amendments, the same as before this work). This record does not make row 13 met: the row is Proposed and outside DR 0004's register, the source is a secondary description of a de facto interface, the pad model has zero delay and ideal pull-ups, and every microsecond figure is core cycles × 20 ns at row 4's unconfirmed 50 MHz target.
