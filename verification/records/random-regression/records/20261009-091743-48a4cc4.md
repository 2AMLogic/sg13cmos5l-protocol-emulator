- **Claim**: Programs **generated from a single recorded seed**
  (`20261009`) by `verification/firmware_templates.py` — 20 UART TX programs
  (1–2 frames; payload classes 0x00 / 0xFF / alternating / random; bit
  periods 50 / 100 / 217 / 250 core cycles), 20 SPI-controller programs
  (modes 0–3 round-robin; 1–2 one-byte CS bursts; SCLK periods 4 / 6 / 8 / 12
  cycles, never above the f_clk/4 ceiling), and 20 I2C-write programs (Fast
  and Standard grade alternating; address and data bytes drawn per class;
  address ACKed in 16 programs and NACKed in 4, taking the BNZ's other arm) —
  are each assembled with the DR 0003 assembler (`asm.assemble_text`), loaded
  over the real serial load-phase pins onto `tt_um_2amlogic_protocol_emulator`,
  executed by `rtl/protocol_core.v`, and graded from the captured pin
  waveform by the existing **independent** models
  (`reference_models/uart.py`, `spi.py`, `i2c.py`). **All 60 programs PASS**:
  UART bytes recovered and `check_frame` inside row 10's bound with every
  edge landing on a whole multiple of the bit period; SPI CPOL idle levels,
  CS envelope and f_clk/4 ceiling conformant with MOSI and MISO decoded
  byte-exact and every SCLK half-period measuring exactly the generated
  value; I2C decoded address/data/ACK pattern exact and the Table 10 t_LOW /
  t_HIGH / t_HD;STA / t_SU;STO measurements equal to the committed
  65/60 (Fast) and 235/200 (Standard) cycle budgets. Negative controls on
  the same DUT-and-model path (below) are **FAILED by the model**, so the
  random layer can fail. This is the DUT-facing half of verification-plan
  §4 that `protocol-reference-models` (#25) explicitly deferred.

  Standard programs with the data-clock low phase 10 cycles short → `t_LOW

  SPI burst with a non-zero MOSI byte is re-graded under the three wrong
  modes and must not round-trip (counted per program in `verdicts.json`).
  **Finding (a model sensitivity, filed as issue #97, recorded not fixed — the models are
  unchanged by this issue).** `UartDecoder._measure_drift` measures only the
  frame's *last* transition, so a frame whose payload is 0xFF (only the start
  edge and the first-data-bit rise, both of which sit at the start of the
  frame) has no late edge and a mistimed transmitter is not detected by
  `check_frame` — the first attempt at the UART negative control with a 0xFF
  payload passed and was caught by this bench's own "must FAIL" assertion.
  For the random UART cases the bench therefore also asserts every edge lands
  on a whole multiple of the bit period (cycle domain), which does cover that
  payload; the mistimed control uses 0x5A. A second finding: the committed
  I2C bench's exact `==` on float-ns measurements (`assert_measured_budgets`)
  misses by ~1e-9 ns late in a long run (hit at index 56 of the opt-in
  60-program sweep); this bench compares with a 1e-3 ns absolute tolerance
  (5e-5 of a cycle) instead of reusing that helper, and the committed bench
  is left unchanged.
