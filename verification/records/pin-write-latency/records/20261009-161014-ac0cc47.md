- **Record ID**: 20261009-161014-ac0cc47
- **Claim**: the formal property `pin_write_latency` (spec/verification-plan.md section 2.2, DR 0001 "Drive on edge") **holds on the shipped core `rtl/protocol_core.v`** within the harness model described under "Design provenance". The property is: every executed `OUT` writes the selected source register's pre-edge value to the addressed writable port at the edge that retires it. The other port holds. No output changes for read-only-port `OUT`s, non-`OUT` instructions, `WAIT` stalls, `HALT`, load phase or the DR 0005 priming cycle. The one exception is reset, which returns both ports to 0. In the FINE clock model, no output changes between rising clock edges. ABC's `scorr` + `pdr` proved every assertion in both clock models. **Within that harness model the result is an unbounded proof**, from one engine family. The scorr-independent bounded cross-check reached only 9 cycles (EDGE) and 14 time samples (FINE); see "Result". All 15 EDGE covers and all 17 FINE covers were reached. All 7 fault-injected core copies were rejected on their required model by both ABC and Z3. The structural check passed on the core and rejected both registration-breaking mutants. **Not claimed**: anything about physical pads, post-route delay, clock skew, setup/hold or the SDF failure (#106); pin roles (#94); programs that need more than 8 distinct instruction words (see abstraction); asynchronous reset assertion between clock edges; the load phase itself; any synthesis or timing number (no flow ran: this is RTL-level only); or ratification of DR 0001/0005, which are still Proposed (DR 0006).
- **Design provenance**: DUT = `rtl/protocol_core.v` (sha256 `b41e474f...392b`), read unmodified, at git `ac0cc47`. Harness `verification/formal/formal_top_pin_write.v`; monitor `verification/formal/pin_write_latency.sv` (sha256 `774980c1...a97c`). **Program abstraction**: 8 free `anyconst` 16-bit words selected by `fetch_addr[2:0]` and read through a register (`instr_q`), which models DR 0005's one-cycle synchronous fetch. Every opcode/register/port/immediate combination is free in each word. Addresses alias modulo 8, so a program is any control flow over at most 8 distinct instruction words. This is the same abstraction the section 2.1 record uses. `rtl/protocol_program_memory.v` and the SRAM macro are not inputs. **Phase/reset model (assumptions)**: `run_phase` follows the program memory's mode_pin-low timing (reset, one mode-sampling edge, then run). The load phase proper is not explored; the core sees `run_phase` low throughout it, exactly as here. Reset is a free per-cycle request (`rst_req`) registered on `clk`, so mid-run resets and HALT-until-reset are explored, but reset only changes at a clock edge. `ui_in`/`uio_in` are free in every solver step. No `assume` statement exists anywhere in the harness or monitor. **Independence**: the monitor derives execution eligibility from the harness phase model (run phase delayed one cycle, not the core's `fetch_valid`) and its own shadow `HALT`/`WAIT` state. Expected values come from a shadow register file written from DR 0001's ISA text. The monitor reads no core-internal signal: no write enable, `waiting`, `halted`, `fetch_valid` or `regs`. It does share the fetched instruction stream (`instr_q`, chosen by the core's `fetch_addr`): which instruction runs next is section 2.1's property, and this one checks what each fetched instruction does to the pins.
- **Clock convention (reconciliation of DR 0001 with verification-plan section 2.2)**: cycle N is the clock period in which `OUT` occupies execute. During N the source register holds the pre-edge value and the port still shows its old value. The edge that ends N is the retiring edge: the output flop captures the value then. From that edge on, cycle N+1, the port shows the new value. The next assertion sampling point in the EDGE model evaluates this post-edge state. DR 0001's "writes at the clock edge that retires the OUT ... visible one clock cycle after OUT executes" and the plan's "retires at cycle N ... value at cycle N+1" label the same event. There is no extra output pipeline stage: the `late_one_cycle` mutant, which adds one, is rejected. So there is **no spec discrepancy and no spec finding**, and nothing was relaxed. The FINE model and the structural check rule out visibility earlier than that edge, including half a cycle earlier.

- **Result**: **PASS.** Each reported item is labelled with its depth and engine.
  - **(R0) Structural check** (Yosys `simplemap` + `select`, no clock model): all 16 bits of `port_uo_out`/`port_uio_out` are Q pins of rising-edge flops (`$_DFF_P*`/`$_DFFE_P*`) clocked by `clk`, with no logic between flop and port. This is what DR 0001's "registered output, not combinational passthrough" means structurally. It says nothing about D, which the proofs cover.
  - **(R1) EDGE proof**: ABC `scorr; pdr -a`, `Properties: All = 6. Proved = 6.` (`core-edge-proof.txt`). The six properties are A1 for each port (`uo_out == exp_uo` and `uio_out == exp_uio`, monitor lines 230-231) and A2 for each port in its update and hold branches (lines 235-236). This is **unbounded, for the harness model above**. `scorr` (inductive signal correspondence) reduces the design from 308 to 244 latches; PDR then closes in 0.03 s.
  - **(R2) FINE proof**: ABC `scorr; pdr -a`, `All = 8. Proved = 8.` (`core-fine-proof.txt`). These are A1/A2 evaluated at every time sample, plus F1 (`formal_top_pin_write.v` lines 149-150): an output may change only in a sample with a rising `clk` edge, whatever `ui_in`, `uio_in` and `rst_req` did meanwhile. **Unbounded, for the harness model, with zero-delay RTL semantics.** `scorr` proved every bad-state signal equivalent to constant 0. The model's limits are that it does not explore reset asserted between edges and that it does not model physical delay or glitches.
  - **(R3) Bounded cross-check without `scorr`** (informational): raw ABC `bmc3` with a 120 s budget found no counterexample in **9 clock cycles** (EDGE) and **14 time samples** (FINE). These depths are shallow. Z3 through `yosys-smtbmc` could not get past BMC step 7 on the positive EDGE model in 300 s (measured while developing the harness), and `pdr` without `scorr` did not converge within 300 s on either model (reached frame 31 EDGE and 21 FINE). **The unbounded result therefore rests on ABC's `scorr`+`pdr` alone.** The evidence that this engine is not vacuous: it disproves the faulty cores (`wrong_destination` 4 of 6 disproved, `negedge_half_cycle_early` FINE 4 of 8 disproved; development runs, not part of this record's artifacts), every cover is reachable, and every mutant is caught.
  - **(R4) Induction**: the PDR result above is the induction-family result. `yosys-smtbmc -i` (k-induction with Z3) was not attempted, because Z3 cannot reach the depth such an attempt would need on this model.
  - **(R5) Covers** (Z3, `yosys-smtbmc -c`; `core-edge-cover.txt`, `core-fine-cover.txt`). EDGE reached all 15 covers within 7 steps. FINE reached all 17 within 13 samples. The covers are:
    - an `OUT` of each of R0-R3 to port 10 and to port 11, each with a nonzero value that visibly changes the pin (8 covers, lines 251-252);
    - back-to-back `OUT`s with distinct values (line 261);
    - back-to-back `OUT`s to port 10 then port 11, where the first pin shows its value while the other port holds (line 264);
    - an `OUT` after a `WAIT` stall (line 266);
    - a read-only-port `OUT` retiring (line 268);
    - a nonzero pin held through a `WAIT` stall (line 270) and after `HALT` (line 272);
    - a mid-run reset returning a nonzero pin to 0 (harness line 129);
    - FINE only: an input change between edges while a nonzero pin is held (harness line 155), and an output update on a rising edge (harness line 158).
