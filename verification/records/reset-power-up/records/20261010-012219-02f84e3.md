# reset-power-up: every flop from `rst_n` alone, on the LibreLane netlist

- **Record ID**: 20261010-012219-02f84e3
- **Claim**: Target-spec row 14 / `spec/verification-plan.md` section 8, on the **LibreLane gate-level netlist of the design with DR 0013's boot ROM** (built from `1dc1842`), zero-delay. (a) Every one of the netlist's 176 flip-flops (all `sg13cmos5l_dfrbpq_1`) has its `RESET_B` driven by the `rst_n` port through buffers only, so `rst_n` alone resets it, and in simulation every flop is at its documented reset value (0) on every edge of the reset pulse whatever state it started in. The one state element `rst_n` does not reset is the SRAM macro (array and registered read port), and it is listed with its justification in `verification/reset_coverage_justifications.json`. (b) From an all-X start and from 8 recorded random starts (every flop and every SRAM word seeded), `uo_out`, `uio_out` and `uio_oe` are free of X/Z and equal 0x00 on every edge from the assertion of `rst_n` to the end of the observation window (the boot program's end plus 64 edges), for all four strap values; after reset no flop is X, and for the three stub straps the whole 176-flop trace is bit-identical across the all-X run and all 8 seeds (for strap 10 every flop but the data registers is, and the pins are). (c) With `MODE` low the core never leaves the boot ROM, the SRAM is never read except as the warm-start check's 256 data reads (0 for the stub straps), the program memory is unchanged, and the core halts in the stub DR 0013's strap table names -- including when the SRAM holds a canary image that drives every pin within five instructions of entry at any address and is shown doing so when it is serial-loaded. Reselect: load the committed UART TX firmware and run it, power-cycle, reset without a reload (safe idle as above), power-cycle, reload and run: the second run's pins and full flop trace equal the first's on all 998 samples (edges 0..997 after the MODE drop), for 2 seeds. Each of the three negative controls fails as required. Flow attribution: the netlist is a LibreLane artifact; the simulation is Icarus + cocotb through the template's `test/Makefile` `GATES=yes`; the coverage listing is a stdlib Python read of that netlist and the PDK's cell models. No klt/Yosys/OpenROAD number is produced or implied. **Not claimed:** behaviour under real delays or reset-release timing (`rst_n` is asynchronous and its release is not synchronized; recovery/removal is an STA question, issue #106's territory); the pads (issue #136); a random SRAM start being a valid signed image (1 in 65,536 by construction for random contents; DR 0013's all-zero image is its own valid signature and would warm-start 256 NOPs, `test_boot_rom.py`'s known weak case); anything about the host's reload, which is issue #118.
