  - **The 99 flip-flops are the entire architectural state**, and they add up
    exactly: 32 for R0–R3, 8 for the PC, 8 for the WAIT counter, 8 for `uo_out`, 8
    for `uio_out`, 2 for Z and C, 1 each for `fetch_valid`, `waiting` and `halted`
    (= 68 in the core), plus 16 shift-register + 8 write-address + 4 bit-counter + 3
    phase/saturation bits (= 31 in the memory). Nothing is hiding.
  - **This is the number that makes the design fit.** The superseded flip-flop
    program memory synthesized to 11,603 cells / **312,062.8896 µm²** on this same
    flow (record
    `verification/records/program-load-phase/records/20260921-185910-248bf61.md`, and
    the 2026-09-22 die-area record). The macro-backed memory is **2,369.6064 µm²** of
    standard cells plus the macro's 28,127.104 µm² footprint = 30,496.7 µm², a
    **10.2× reduction** in the memory's total silicon cost on this flow.
  - **Area arithmetic against the ratified ≤2×2 budget** (spec/target-spec.md row 7),
    stated as arithmetic and labelled as such: cells 10,323.2556 µm² + macro
    28,127.104 µm² = **38,450.36 µm²** against the 2×2 core area of
    **126,685.0368 µm²** (die 419.52 × 313.74 µm from `tile_sizes.yaml`, inset by this
    repo's own `src/config.json` margins — the model validated to 4 decimal places in
    DR 0005 Finding 2) = **30.35 % core density**, inside the template's own
    `PL_TARGET_DENSITY_PCT: 60`. **This is not a die area and not a placement
    result**: nothing here has been floorplanned, and the klt flow's own P&R leg is
    blocked by a tool gap (see
    `verification/records/die-area-baseline/records/20260930-195410-ead870a.md`). The
    real area verdict is the LibreLane `gds` run's.
  - **The blackbox, and what it costs this number.** `klt synthesize` has no request
    field for a hard macro, so Yosys aborted outright
    (`ERROR: Module '\RM_IHPSG13_1P_256x16_c2_bm_bist' … is not part of the design`)
    until `flow/blackbox-RM_IHPSG13_1P_256x16_c2_bm_bist.v` — a `(* blackbox *)`
    port-only declaration transcribed from the PDK's own model — was added to both
    recipes' `sources`. That is filed upstream as **2AMLogic/klayout-tools#2635**
    under `CLAUDE.md`'s friction protocol, and it is the same gap that blocks this
    flow's `sta` and `place-and-route` legs (which the stub-only Verilog blackbox
    does *not* fix, because their failure is at the LEF level). **Consequence for
    every number in the table above: the macro contributes 0 µm² to `area_um2`.** The
    28,127.104 µm² is added by hand in the arithmetic above and must be added by hand
    by any later reader; klayout-tools#2635 also asks for the response to mark cells
    that have no liberty area, so this stops being a footgun.
