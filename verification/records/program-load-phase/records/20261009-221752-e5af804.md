- **Claim**: DR 0001's serial load protocol -- MODE latched only at the first edge after `rst_n` release, MSB-first shift from `ui_in[0]`, commit on a word's 16th bit's own edge at an auto-incrementing address, mid-word drop discarded, saturation at 256 words, no mid-run re-entry -- holds **unchanged** on `rtl/protocol_program_memory.v` with the fetch read gate added. One test's name needs reading with care: `test_mode_low_at_release_enters_immediate_run` checks that the *module* raises `run_phase` at the mode-sampling edge when MODE is low. This module-level bench has no core, so its reset helper now holds `fetch_en` high (four added lines, no other change): it reads the array through the fetch port, as the core does once it runs from memory. What `fetch_en` low does is checked on the top, white-box, in `verification/records/boot-rom/`.
