- **Record ID**: 20260930-195410-ead870a
- **Claim**: the DR 0001 serial load protocol — MODE latched only at the first clock
  edge after `rst_n` release, bits shifted MSB-first from `ui_in[0]` one per clock
  edge, a word committed on its 16th bit's *own* edge at an auto-incrementing address
  from 0, mid-word drop discarded, saturation at 256 words with no wraparound, and no
  mid-run re-entry without a fresh reset — holds **unchanged** now that
  `rtl/protocol_program_memory.v`'s storage is the `RM_IHPSG13_1P_256x16_c2_bm_bist`
  SRAM macro instead of a flip-flop array. This is the re-verification DR 0005 named
  explicitly as the likeliest thing to be skipped: *"`verification/test_program_memory.py`
  must be re-verified against the macro-backed module, not assumed to carry over …
  the bench's contracts are unchanged — only the sampling cycle moves. This is named
  explicitly because silently assuming the existing bench still applies is the
  likeliest way to ship an unverified change."*

- **Result**: **PASS — 6/6, and the contracts are unchanged.** (0 failed, 0 skipped;
  per-test statuses in `artifacts/20260930-195410-ead870a/results_icarus.xml`.) Each
  of the six tests is the *same* test as in the superseded record, asserting the same
  contract with the same stimulus: MODE low at release enters run immediately; a
  single 0x1234 loads MSB-first and survives a MODE drop on the edge right after its
  16th bit (commit-on-16th-bit-edge); a full 256-word program reads back exactly at
  every address 0..255; a mid-word MODE drop commits nothing and leaves the canary at
  `mem[1]` intact while the next reset realigns the writer to address 0; a run-phase
  MODE-high reprogram attempt writes nothing; and streaming 300 words saturates at
  256 without wrapping over the loaded program.
  - **Load timing is unchanged and still asserted cycle-exact**: a full 256-word load
    spans exactly 4,097 clock edges from the mode-sampling edge to the MODE-drop exit
    edge (1 sampling + 16 × 256 bit edges + 1 exit), 16 cycles per word. The macro
    swap moved nothing here, because the commit is still driven by the same
    `{shift_reg[14:0], serial_in}` expression on the same edge — it is now the macro's
    `A_DIN`/`A_WEN` at that edge rather than an array assignment.
  - **The one thing that did move, and the only thing:** the fetch port's read
    latency. The macro's read is synchronous with one-cycle data access, so
    `fetch_word()` in the bench now presents the address, advances **one clock edge**
    and reads `instr_word` after that edge — where the superseded bench settled a
    combinational read with a bare 1 ns timer hop. That is DR 0005's amendment seen
    from the memory's side, and it is the entire diff in this bench. Nothing else in
    the file changed.
  - **No silicon clock is claimed.** Load timing is stated in *cycles*; the 81.94 µs
    arithmetic the superseded record quoted at the draft 50 MHz still follows from
    4,097 edges, and is still arithmetic rather than a measurement. Target-spec row 4
    remains unconfirmed on both flows, and on this flow it is now additionally
    *blocked* — see
    `verification/records/sta-corner-sweep/records/20260930-195410-ead870a.md`.
