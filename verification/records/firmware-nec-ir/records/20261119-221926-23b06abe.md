# firmware-nec-ir — 20261119-221926-23b06abe

- **Record ID**: 20261119-221926-23b06abe
- **Claim**: NEC infrared remote firmware on the frozen ISA, multi-protocol extra credit (issue #448; catalog #443), RTL leg, transmit path. The committed program `firmware/asm/nec_ir.asm` (image `firmware/build/nec_ir.hex`, 164 words of the 256-word store: 131 code + 33 table), loaded over the serial load-phase pins onto the RTL top and executed by the ISA core, drives NEC frames on IR_TX = `uo_out[7]` (DR 0010's `nec_ir_tx` role, added by this issue) that the independent NEC receiver model `verification/reference_models/nec_ir.py` (written from the protocol description alone, demodulator included) decodes: one latched frame per transmission with the address and command matching the loaded table (committed 0xA5/0x3C; a seeded random 0x87/0x65 in its own run), both complement pairs checked, zero violations. Cycle-domain, at the pin: every carrier period exactly 1,316 cycles (439 high; the leader's two 171-period halves join seamlessly because the 8-bit burst counter forces halves and the junction completes its low), leader mark exactly 449,195, leader space exactly 225,000, bit and final marks exactly 28,075, spaces exactly 28,125 (0) and 84,375 (1), inter-frame idle exactly 3,000,000 (measured through into the next frame's leader). Firmware only on the frozen DR 0017 ISA: no RTL file changed, no hardware peripheral; the receiver-module input `ui_in[4]` (the `nec_ir_rx` role) is board wiring — the RX decode firmware is the recorded follow-up. Every us/kHz figure is core cycles x 20 ns at target-spec row 4's **unconfirmed** 50 MHz target; the graded claims are the cycle counts.
