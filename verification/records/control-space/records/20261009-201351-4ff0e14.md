- **Record ID**: 20261009-201351-4ff0e14
- **Claim**: The RTL implements DR 0012's control space (`spec/decision-records/0012-control-space-and-runtime-pin-direction.md`, **Proposed, not ratified**) as that record's sections 1-2 state it, checked by the record's own "control-register bench" obligation plus issue #135's program-memory and CRC checks. Specifically: (a) every register resets as the record says and `uio_oe` is 0 from reset until a program writes a pin-mode register; (b) `UIO_DIR`, `UIO_OD` and `PM_ADDR` read back what was written, and `uio_oe` follows the pin-mode rule (open-drain wins, then push-pull, else input) on the edge the write retires; (c) a write to an unassigned or read-only index changes nothing, a read of an unassigned or write-only index returns `0x00`, each in 1 cycle, and `OUT` to port 01 / `IN` from port 11 stay no-ops for every `imm8` tried; (d) `WCTL PM_DATA_LO`, `RCTL PM_DATA_HI` and `WCTL RUN` cost exactly 2 cycles and every other access exactly 1, on the same edges for four different data sets; (e) no control access changes `Z` or `C`; (f) words written through `PM_ADDR`/`PM_DATA_*` read back, leave their neighbours alone, auto-increment and wrap the address, execute when entered with `RUN`, and a write to the word fetched next takes effect; (g) `PM_CRC` equals `binascii.crc_hqx` (CRC-16/XMODEM, an implementation this repository did not write) over the serial load, over `PM_DATA_LO` commits, over both without a clear in between, and after a clear through either register; (h) after the preamble the six committed I2C images gained, `uio_oe == ~uio_out & 0x81` on every edge. **Scope boundary.** RTL simulation under Icarus. `uio_oe` is checked as a logic output: this is **not** a pad model and not evidence that an I2C bus is driven correctly (issue #136). The load-phase CRC readout on `uo_out` (issue #137) and the boot ROM (issue #138) do not exist and are not exercised; `BOOT_STATUS[1]` therefore reads 0. No clock frequency, area or timing claim: those are the synthesis-baseline and librelane-corner-timing records at this commit. The gate-level run of this same bench is `verification/records/firmware-gate-level/`.
- **Design provenance**: `rtl` -- `src/tt_um_2amlogic_protocol_emulator.v`, `rtl/protocol_core.v`, `rtl/protocol_program_memory.v` and the vendored macro model @ `4ff0e14`. Choices the RTL makes where DR 0012 is silent, stated so they are not mistaken for the record's: `HW_ID` is `0x01` (a module parameter); the CRC takes each word high byte first (the order of DR 0013's big-endian UART frame); a write to `PM_CRC_LO` or `PM_CRC_HI` clears all 16 bits; a write to read-only `BOOT_STATUS`/`HW_ID` and a read of write-only `RUN` behave as unassigned indices; `BOOT_STATUS[0]` is set when a load phase ends, whatever it loaded. No synthesis, P&R or layout is involved in this record.
