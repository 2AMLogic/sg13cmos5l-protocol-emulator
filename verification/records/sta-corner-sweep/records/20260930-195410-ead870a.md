- **Record ID**: 20260930-195410-ead870a
- **Claim**: this record makes a **negative** claim, and that is its whole point. The
  klt-flow six-corner STA sweep that the superseded records ran over the
  harness-bootstrap stub **cannot be run at all** over the real ISA core, because
  `klt sta`'s request schema has no way to declare the program-memory SRAM macro's
  LEF or liberty. The previous record's timing numbers were the stub's and were
  already explicitly not row-4 evidence; this record retires them and states that
  the replacement measurement **does not exist**, rather than leaving a stale
  stub-era number standing next to a design it no longer describes.
- **Design provenance**: `netlist` (post-synthesis) from `rtl` sources @ `ead870a` —
  `src/tt_um_2amlogic_protocol_emulator.v` + `rtl/protocol_core.v` +
  `rtl/protocol_program_memory.v`, the macro-backed ISA core. The synthesis step of
  the sweep succeeded; the STA step is where it stops.
- **Run configuration**: `KLT_BIN=<repo>/.venv/bin/klt ./flow/run-sta-corner-sweep.sh`
  from the repo root, unmodified, at the `layout/toolchain.json` pin (`klt 0.6.0`,
  commit `c622e8addb362491664d44ba4d717f354ca88bbd`) with `openroad` on `$PATH`. The
  runner synthesizes once at the nominal corner (`typ_1p20V_25C`, Yosys `0.67+post`)
  and then runs one `klt sta` per corner over that one netlist, in verilog mode with
  `clock_port: clk`, `clock_period_ns: 20.0`, `wire_load_model: "1k"`,
  `wire_load_mode: "top"` — i.e. exactly the configuration the superseded record
  used, with only the design changed.
- **Statistical convention**: N/A — six deterministic single-corner runs over one
  fixed netlist, no seed, no sampling.
- **Result**: **FAIL / BLOCKED — 0 of 6 corners produced a timing result.** Every
  corner (`slow_1p08V_125C`, `slow_1p35V_125C`, `typ_1p20V_25C`, `typ_1p50V_25C`,
  `fast_1p32V_m40C`, `fast_1p65V_m40C`) failed in 1–2 s with the identical error
  before any timing analysis began:

  ```
  [ERROR ORD-2013] instance u_prog_mem/u_sram LEF master
  RM_IHPSG13_1P_256x16_c2_bm_bist not found.
  ```

  - **This is a tool gap, not a design defect.** `klt.sta.request/1` carries
    `pdk.cell_library` + `pdk.corner` and nothing else: there is no field for an
    extra LEF, and none for the macro's own per-corner liberty. OpenROAD therefore
    never reads the macro's abstract and cannot even load the netlist. Filed upstream
    as **2AMLogic/klayout-tools#2635** under `CLAUDE.md`'s friction protocol
    (described as a tool gap, with this design's specifics left out). It is the same
    gap DR 0005 anticipated in its **open item 4** — *"a klt-side place-and-route flow
    that handles a hard macro against this PDK … if that surfaces a tool gap, it is a
    2AMLogic/klayout-tools issue"* — and the same one that blocks this flow's
    place-and-route leg (`verification/records/die-area-baseline/records/20260930-195410-ead870a.md`).
  - **The Verilog blackbox that unblocked synthesis does not help here**, and it is
    worth saying why: `flow/blackbox-RM_IHPSG13_1P_256x16_c2_bm_bist.v` is an
    RTL-level declaration, and this failure is at the LEF/abstract level. One
    workaround covers one of the three verbs.
  - **Target-spec row 4 (≥50 MHz) is therefore unconfirmed on this flow, and now for
    a second, independent reason.** The first was already recorded: `klt synthesize`
    reports `timing: null` for `sg13cmos5l_stdcell` ("no verified mapping for ABC
    timing"), so this flow has never produced a timing number for this library from
    synthesis either. The LibreLane flow of record runs its own STA inside the `gds`
    workflow and is the only path to a row-4 number today; per `CLAUDE.md`'s
    two-flows rule that number, when it exists, is reported as LibreLane's and is not
    interchangeable with anything this runner would have produced.
  - **What the superseded record said, preserved**: its six-corner
    `timing_status: "constrained"` results were the **stub's** (16 cells), were
    labelled by its own author as toolchain bring-up rather than row-4 evidence, and
    were a pre-layout `netlist_estimate` besides. Nothing in it is contradicted here
    — its DUT simply no longer exists.
  - **What would unblock this leg**: either klayout-tools#2635 (a `macros` block in
    the `sta` request), or a klt release that lets `pdk` name more than one library.
    Until then this runner should not be re-run against this design expecting a
    result; the failure is deterministic and reproduces in seconds.
