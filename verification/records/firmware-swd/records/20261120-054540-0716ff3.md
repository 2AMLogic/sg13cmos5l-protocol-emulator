- **Claim**: SWD debug probe on the frozen ISA, multi-protocol extra credit (issue #452; DR 0018's dated note of 2026-11-19), RTL leg, **revised after the review of PR #501**. The committed program `firmware/asm/swd_probe.asm` (image `firmware/build/swd_probe.hex`, **227 words** of the 256-word store, 218 SWCLK rising edges on the OK path, 1,179 model edges) acts as the SWD **host** on SWCLK = `uio[2]` and SWDIO = `uio[3]`: line reset, the 0xE79E switch, a second line reset, two idle clocks, then two DP reads (0xA5, 0xBD) against the independent scripted target `verification/reference_models/swd.py`. Three things changed from the superseded record, each a review finding: (1) **ACK wire order** -- the oracle had OK = 0,0,1; ADIv5 numeric codes OK=1, WAIT=2, FAULT=4 are sent LSB first, so the wire carries OK = **1,0,0**, WAIT 0,1,0, FAULT 0,0,1 (IHI 0031H B4.1.5); model, bench and docs corrected, so the superseded record's `ACK 001` / `WAIT = ACK 010` / `FAULT = ACK 001` readings are the wrong bit order and its FAULT case in fact exercised an OK-shaped reading; (2) **WAIT/FAULT end the transfer** -- the error cases moved to the second request (RDBUFF; DPIDR must answer OK), the target ends after the ACK and turnaround (ORUNDETECT = 0), and the probe branches on the first ACK bit (two `BZ`s, the documented handshake case of the data-dependent-latency lint), clocks the remaining ACK slots, leaves the return turnaround released, re-drives SWDIO low and idles eight clocks, instead of clocking 36 slots into a pulled-up line; (3) **return-turnaround ownership** -- the model now grades a released turnaround cycle after the last response bit (`return-turnaround-driven`) and a line released after the transfer (`line-released-after-transfer`).
