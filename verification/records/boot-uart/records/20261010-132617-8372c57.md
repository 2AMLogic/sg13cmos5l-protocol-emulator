- **Claim**: DR 0013 layer 2's UART load (`spec/decision-records/0013-program-loading.md`, **Proposed, not ratified**), as issue #139 scopes it, works on the RTL of the submitted top: **a PC on the demo board's USB-UART bridge pins (Tiny Tapeout option B: RX `ui_in[1]`, TX `uo_out[0]`) loads a program into a chip with nothing else attached, and the chip runs it only if it arrived intact.** Specifically, against an independent host model (`verification/uart_boot_host.py`, own CRC and own line timing, no import from `firmware/`): (a) a framed image (`0xA5`, `N-1`, `2N` bytes high first, CRC-16/XMODEM) at 434 cycles per bit is accepted, answered `0x06` + the chip's CRC (equal to `binascii.crc_hqx`'s), and run from address 0 with `R0`-`R3`, `PM_ADDR`, `UIO_DIR`, `UIO_OD` and `BOOT_STATUS` at their reset values, with program memory equal to the image word for word (RTL white-box); (b) the same at host bit-rate errors of -2 % and +2 % (target-spec row 10's bound), back to back and with idle bits, with edge jitter, and with the unrelated `ui_in` bits toggling, and a sweep past the bound that records where it stops (works to +5 % (host slow) and -4 % (host fast)); a host 12 % off in either direction is not accepted (the negative control); (c) a flipped payload bit (three positions), a bad CRC (high byte, low byte, both), a length too small (three variants) or too large, a wrong magic and a magic byte alone are never run: the reply is `0x15` or none, the core never leaves the boot ROM, `uio_oe` stays 0, `uo_out` stays at idle-high TX, and a correct frame sent afterwards is accepted; (d) garbage ahead of the magic is ignored; (e) end to end, the committed `uart_tx` program is loaded over the UART and its frames are decoded and graded by the existing independent `reference_models/uart.py` (`check_frame`, row 10); (f) a 256-word signed image (count byte `0xFF`) loads and then survives a warm start; (g) strap `11` and a failed warm start fall through to the loader; (h) the host model's frame equals `firmware/tools/loadseq.py`'s byte for byte for nine committed and constructed images, both agreeing with `binascii.crc_hqx`.
