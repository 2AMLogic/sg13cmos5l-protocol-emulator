- **Record ID**: 20261009-201346-4ff0e14
- **Claim**: The reset/pin contract this experiment carries still holds on the control-space core, and its *reason* changed: **after `rst_n`, both pin-output registers read 0 and `uio_oe` reads 0, and the load phase changes neither.** In `20260930-195410-ead870a` `uio_oe` was 0 because the top level assigned a constant. Since issue #135 `uio_oe` is driven from the core's `UIO_DIR` / `UIO_OD` control registers (DR 0012), and it is 0 after reset because both registers reset to 0 -- DR 0012's "Reset values: everything is an input". So `uio_oe == 0` is no longer a property of the netlist for all time; it is the reset state, and firmware can change it. That record's statement that an `OUT` to port 11 "can never move `uio_oe`" is still true of `OUT` (only `WCTL` moves it), but is no longer true of firmware in general.
