- **Record ID**: 20260930-195410-ead870a
- **Claim**: **the behaviour this experiment recorded no longer exists, and this
  record says why.** The superseded record `20260914-031931-7e4a21a` measured the
  harness-bootstrap stub top (issue #2): `ui_in` registered onto `uo_out` on every
  `clk` edge while `ena` was high, cleared on `rst_n` low, `uio_oe` held at 0. Issue
  #18 replaced that stub with the ISA core datapath, so the top no longer registers
  `ui_in` onto `uo_out` at all — what drives the output pins now is firmware loaded
  over DR 0001's serial load phase. Per `CLAUDE.md`, "a result is not superseded by
  deletion, it is superseded by a later record that says why"; this is that later
  record, and this bullet is the why.
  What **is** claimed here is the surviving half of the stub's contract, now checked
  through the core: **after `rst_n`, both pin-output registers read 0 and `uio_oe`
  reads 0**, and the load phase changes neither. That is checked by
  `test_reset_and_load_leaves_pins_cleared` in the same file at the same path
  (`verification/test_protocol_emulator.py`, driven by the same
  `verification/request-protocol-emulator.json`), which is why this experiment's
  chain continues here rather than simply ending.
- **Design provenance**: `rtl` — `src/tt_um_2amlogic_protocol_emulator.v` @

- **Result**: **PASS, with the old claim formally retired.**
  - **13/13 directed cases passed** (0 failed, 0 skipped). The reset/pin contract this
    experiment is named for is `test_reset_and_load_leaves_pins_cleared`: with a
    one-word `HALT` program loaded over the real load-phase pins, `uo_out`,
    `uio_out` and `uio_oe` all read 0 through reset, through the load phase, at the
    instruction's retirement, and for 10 further cycles after `HALT` freezes the core.
  - **`uio_oe == 0` is unchanged from the stub and is now checked in three separate
    tests**, including `test_out_port11_drives_uio_out_not_oe`, which pins the reason:
    DR 0001 makes direction a synthesis-time decision, so an `OUT` to port 11 writes
    `uio_out` and can never move `uio_oe`.
  - **The stub's pin-through behaviour is gone, deliberately.** There is no longer any
    path from `ui_in` to `uo_out` that does not go through a loaded instruction. A
    reader looking for the old `ui_in -> uo_out` latency should read the superseded
    record for what the stub did, and
    `verification/records/core-datapath/records/20260930-195410-ead870a.md` for what
    the design does now (in particular `test_in_ports_and_direction_noops`, which is
    the nearest analogue: an `IN` from port 00 followed by an `OUT` to port 10, at
    two cycles plus the "Drive on edge" latency rather than one).
  - **`ena` is no longer a gate.** The stub's `test_ena_gates_updates` checked that
    `uo_out` held while `ena` was low. The core does not consume `ena` at all — DR
    0001's load protocol is reset-gated, and the Tiny Tapeout template documents `ena`
    as "always 1 when the design is powered, so you can ignore it". That assertion is
    therefore **withdrawn, not silently dropped**: it described a stub behaviour that
    was never part of the ISA contract.
  - **`verification/_dut.py` is no longer imported by this bench** (the new bench
    resets through its own `load_program()`, which must drive MODE high before
    releasing `rst_n` — something the shared helper does not do). The file is left in
    place unchanged: it is still cited by
    `verification/records/post-layout-sdf-regression/`'s chain, and deleting it would
    break records that are not this issue's to re-mint. It is hashed above at its
    current (unchanged) content.
