  `tt_um_2amlogic_protocol_emulator` and executed by
  `rtl/protocol_core.v`, drive write transfers to static address 0x50

  `verification/reference_models/i2c.py` — which shares no code with this
  repo's RTL or firmware and grades against NXP UM10204 Table 10's own
  minimums, not DR 0001's arithmetic — judges conforming in **both speed
  grades**, with every measured phase exactly on the committed cycle
  budget: **t_LOW = 65 / t_HIGH = 60 core cycles (Fast)** and
  **t_LOW = 235 / t_HIGH = 200 (Standard)**, t_HD;STA = 65 / 205,
  t_SU;STO = 60 / 205. The address-ACK handshake flows through the core's
  real `IN` path and is branched on (`BNZ`, DR 0001's one sanctioned
  data-dependent branch) in **both directions**: peripheral-ACK run
  decodes `0x50 W + 0x5A, acks=[True, False]`; peripheral-NACK run decodes
  `0x50 W only, acks=[False]` — a different, shorter waveform from the
  same committed program, which is what makes the branch load-bearing.
  This is issue #73's scope, the I2C third of issue #23, and it is what
  `CLAUDE.md`'s "firmware is evidence" requires of a protocol claim.

  - **ISA finding: DR 0001's I2C cycle-budget sketch holds, at the
    phase level, on the real core** — 65/60-cycle Fast phases and
    235/200-cycle Standard phases are exactly the sketch's allocation,
    measured at the composed line. Two reconciliation notes worth
    recording rather than leaving as unexplained discrepancies: (a) the
    sketch's per-phase bodies (`OUT`+`IN`+`WAIT 62` / `OUT`+`WAIT 58`)
    don't map literally onto a full transfer, because a data bit's SDA
    level must persist **through** the SCL rise (the sketch's low-phase
    `IN` is only right for the ACK slot; every data clock needs its own
    prep, so the per-bit body is `OUT`/`WAIT`/`OR` + `OUT`/`SHF`/`WAIT`/
    `MOV`/`AND`); (b) the sketch's single-`WAIT` claim holds — every
    phase literal (max 232) fits `WAIT`'s 256-cycle ceiling, no loops
    needed for timing. **A second, genuine ISA finding**: the sketch's
    "largest inner loop ... on the order of a few dozen instructions"
    sizing narrative assumed loops, but a per-bit loop needs **five live
    values** (byte, mask, SCL constant, temp, trip counter) and DR 0001's
    ISA has **four registers** — so the eight clocks per byte are
    unrolled straight-line code (65 instructions per byte, 181 words per
    program). One protocol fits the 256-word memory with headroom, but
    "all three core protocols coexist ... with room for a dispatch/mode
    table" (the sketch's own sizing rationale) is now questionable: UART
    34 + I2C 181 + an SPI program of similar unrolled shape would exceed
    it. No spec change made here — rows 1/6 are unaffected as written;
    this is recorded as a finding for the SPI sub-issue and any future
